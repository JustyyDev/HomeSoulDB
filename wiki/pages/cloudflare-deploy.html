Cloudflare Deploy

Use one repo for the wiki, the catalog pipeline, and the HomeSoul Cove API.

This setup keeps the persistent online layer off your local desktop while still letting GitHub stay the source of truth for docs, catalog entries, and deployment automation.

Recommended domain split

`api.soulscorch.org` for the Worker API, `wiki.soulscorch.org` for docs, and your current Vercel-bound root domain left untouched unless you explicitly want to migrate it later.

Deployment pieces

Cloudflare Pages

Serves the static wiki from the `wiki/` folder. No framework build is required for the current site.

Cloudflare Worker

Serves API routes for catalog access, Cove presence, chat, and voice-room metadata from `worker/index.js`.

D1 and KV

D1 handles structured runtime state. KV handles cache-friendly content such as catalog responses.

GitHub Actions

Validates HomeSoulDB submissions and can deploy Worker or Pages changes from the repo.

Root settings

Pages project name: homesouldb-wiki
Production branch: main
Framework preset: None
Build command: leave blank
Output directory: wiki
Root directory: /

Worker project name: homesouldb-cove-api
Deploy command: npx wrangler deploy --config wrangler.toml --name homesouldb-cove-api
